# AIPO Codex Prompt Pack

## 1. 문서 해석용
업로드한 설계서와 요구사항 정의서를 기준으로 AIPO 백엔드의 핵심 도메인을 정리해줘.
다음 기준으로 나눠줘:
1) 사용자 기능 도메인
2) 관리자 기능 도메인
3) AI/RAG 도메인
4) 데이터 파이프라인 도메인
5) 공통 인프라 도메인
아직 코드는 수정하지 말고 구조만 설명해줘.

## 2. AGENTS.md 검토용
업로드한 문서와 저장소 구조를 기준으로 현재 AGENTS.md가 부족한 부분을 찾아줘.
특히 다음을 검토해줘:
- 기능 누락
- 권한 분리 규칙
- RAG 파이프라인 규칙
- 관리자 기능 범위
- 테스트 관점 누락

## 3. 기능 설계 전 계획용
설계 문서를 기준으로 공모주 상세 조회 기능을 구현하려고 한다.
먼저 다음만 정리해줘:
1) 관련 도메인
2) 필요한 엔드포인트
3) request/response DTO 후보
4) service 책임
5) repository 조회 포인트
6) 테스트 포인트
아직 코드는 수정하지 말아줘.

## 4. 문서-코드 비교용
현재 backend 코드와 설계 문서를 비교해서
1) 이미 구현된 기능
2) 아직 구현되지 않은 기능
3) 설계와 코드가 불일치하는 부분
을 체크리스트 형태로 정리해줘.

## 5. 작은 단위 구현용
설계 문서를 기준으로 공모주 상세 조회 기능 중 DTO와 응답 스키마만 먼저 구현해줘.
기존 패키지 구조와 네이밍 규칙을 유지하고,
컨트롤러/서비스 로직은 아직 건드리지 말아줘.

## 6. 인증 기능용
요구사항 정의서를 기준으로 사용자 인증 기능을 구현하려고 한다.
로그인, 회원가입, 로그아웃, 탈퇴 요청까지 포함해서
1) 엔드포인트
2) request/response DTO
3) validation 포인트
4) 예외 처리 포인트
를 먼저 제안해줘.

## 7. 관리자 기능용
관리자 대시보드의 활성 사용자 수 조회 기능을 먼저 구현하려고 한다.
일간/주간 활성 사용자 수 집계를 위한
1) API 설계
2) 서비스 책임
3) 집계 쿼리 방향
4) 응답 포맷
5) 권한 체크
를 먼저 정리해줘.

## 8. RAG 파이프라인용
설계 문서를 기준으로 신규 공시 PDF 업로드부터 텍스트 추출, 임베딩 생성, 벡터 DB 저장까지의 백엔드 처리 흐름을 단계별로 설계해줘.
배치/비동기 처리 여부도 함께 제안해줘.

## 9. 리팩터링용
현재 코드에서 사용자 API와 관리자 API가 섞여 있는 부분이 있는지 찾아줘.
있다면 어떤 기준으로 분리하면 좋은지 변경 계획만 제안해줘.

## 10. 마무리 검토용
이번 변경 사항이 설계 문서와 맞는지 검토해줘.
다음 기준으로 점검해줘:
- 기능 누락 여부
- 권한 분리
- 응답 스키마 일관성
- 예외 처리
- 테스트 포인트
